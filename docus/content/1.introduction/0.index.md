# What is MassTransit?

MassTransit is an open-source distributed application framework for .NET that provides a consistent abstraction on top of the supported message transports. The interfaces provided by MassTransit reduce message-based application complexity and allow developers to focus their effort on adding business value.

### Message Routing

MassTransit supports type-based publish/subscribe and automatically configures the broker topology to route messages by message type. When supported by the broker, polymorphic message type routing is used.

### Retry, Redelivery

Bad things happen, and when they do consumers throw exceptions. To prevent message loss, MassTransit only acknowledges and/or removes messages from the broker after they have been consumed successfully. To deal with exceptions, MassTransit can be configured to retry (within the same message delivery) or re-deliver (by returning the message to the queue) messages using retry policies and exception filters. When retries and/or redeliveries are exhausted, messages that cannot be succesfully consumed are moved to an *_error* queue.

### Sagas, State Machines

Sagas are useful orchestration tool, and MassTransit makes creating powerful, event-driven state machines with durable state easy. By combining durable, guaranteed message delivery with persistent, event-driven saga state machines, sophisticated business logic can be implemented with built-in reliability, availability, and scalability.

### Unit Testing

Asynchronous programming is hard, which means creating consistent and trusted asynchronous unit tests is downright difficult. By using MassTransit's test harness, consumer, saga, and routing slip activity unit tests can be built and executing with a lightning fast in-memory transport.

### Observability

MassTransit has native support for Open Telemetry (OTEL) and uses Microsoft's `ActivitySource` to emit activity start/stop events.

### Serialization

In MassTransit, messages are plain-old-CLR-objects (POCOs) and can be defined using classes, interfaces, or records. To send or receive a message, MassTransit uses a serializer to convert the message into bytes that can be transfered via the broker. By default, messages are encapsulated in an envelope and serialized as JSON. Raw (no envelope) JSON is also supported. XML (either with or without an envelope) serialization is also available.

### Connection Management

Distributed applications are networked, and the network is unreliable. MassTransit manages connecting (and reconnecting) to the message broker and ensures that all messaging entities (queues, topics, exchanges, subscriptions, etc.) have been created (and recreated, if necessary).

### Dependency Injection

MassTransit configures the built-in .NET service collection, ensuring that consumers, sagas, and routing slip activities are properly registered in the container. Consumers use a scoped lifetime and middleware filters (consumed, publish, and send) can also be scoped.
